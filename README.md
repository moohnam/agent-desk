# Agent Desk

TweetDeck처럼 여러 컬럼에서 CLI 에이전트(Claude Code, Codex) 작업을 보고, 지시하고, 승인하고, 이어서 진행하는 로컬 우선 데스크입니다. 같은 네트워크의 폰에서도 열 수 있고, macOS 데스크톱 앱(Tauri)으로도 띄울 수 있습니다.

현재 구현의 사용 기술·데이터 흐름·설계와 제약은 [기술과 구현 설계](docs/technology-and-design.md)를 참고하세요.

## 구성

| 위치 | 역할 |
| --- | --- |
| `hub/` | HTTP 서버(기본 `:4317`). 프로젝트·작업·이벤트를 SQLite(`node:sqlite`)에 저장하고, SSE로 화면에 실시간 전달합니다. 빌드한 웹 화면도 함께 제공합니다. |
| `hub/src/runner/` | 러너 데몬(`127.0.0.1:4318`). 에이전트 세션(Claude Agent SDK, `codex app-server`)을 실제로 실행합니다. 허브와 분리되어 있어 허브를 재시작해도 실행 중인 세션이 끊기지 않습니다. |
| `web/` | React + Vite 화면. 컬럼, 스레드, 작성 서랍, 승인 대기열, 검색, 스킬 관리. |
| `desktop/` | 허브 화면을 창 하나로 띄우는 Tauri v2 셸. Finder에서 끌어다 놓은 파일의 절대 경로를 전달합니다. 자세한 내용은 [`desktop/README.md`](desktop/README.md). |

## 설치

### 한 번에 설치·실행 (에이전트용)

사람이 해야 하는 일은 Claude Code 로그인(`claude` 실행 후 브라우저 인증)과, Codex를 쓸 경우 `codex login`뿐입니다. 나머지는 아래 명령을 차례로 실행하면 됩니다. `npm start`는 끝나지 않는 서버이므로 백그라운드로 띄웁니다.

```sh
node -v                       # v26 이상이어야 함
claude --version              # Claude Code가 설치·로그인되어 있어야 Claude 작업이 돎
git clone https://github.com/moohnam/agent-desk.git
cd agent-desk
npm install                   # fsevents install-scripts 경고는 무시해도 됨
npm run build
mkdir -p data
nohup npm start >> data/hub.log 2>&1 &
sleep 3
curl -s http://127.0.0.1:4317/api/state   # {"projects":[],...,"runner":{...}} 이 오면 성공
```

- 이미 다른 허브가 떠 있으면 포트를 바꿉니다: `PORT=4417 RUNNER_PORT=4418 nohup npm start ...`. 러너 포트도 함께 바꿔야 기존 러너와 섞이지 않습니다.
- 동작 확인용 작업 하나 보내기(도구를 쓰지 않아 승인 없이 끝남):

  ```sh
  mkdir -p /tmp/desk-try
  curl -s -X POST -H 'content-type: application/json' \
    -d '{"text":"@try:/tmp/desk-try #haiku 도구를 쓰지 말고 OK 한 단어로만 답해"}' \
    http://127.0.0.1:4317/api/compose
  curl -s http://127.0.0.1:4317/api/state   # 몇 초 뒤 tasks[0].status 가 "done"
  ```

- 접속 토큰(`data/access-token`)과 `data/hub.log`(토큰이 든 접속 주소가 찍힘)는 출력하거나 공유하지 않습니다.

### 1. 준비물

| 항목 | 용도 | 설치 |
| --- | --- | --- |
| Node.js 26 이상 | 허브·러너 실행 (TypeScript를 빌드 없이 직접 실행하고 `node:sqlite`를 씀) | https://nodejs.org 또는 `brew install node` |
| Claude Code | Claude 작업. 앱이 띄우는 세션은 이 로그인 정보를 씀 | `npm install -g @anthropic-ai/claude-code` 후 `claude`를 한 번 실행해 로그인 |

| Xcode Command Line Tools, Rust (선택) | macOS 데스크톱 앱 빌드 | `xcode-select --install`, https://rustup.rs |

`node -v`가 `v26` 이상인지 확인합니다. Codex를 쓰지 않으면 Codex CLI 없이도 동작합니다(Codex 작업만 실패).

### 2. 받아서 빌드

```sh
git clone https://github.com/moohnam/agent-desk.git
cd agent-desk
npm install
npm run build    # web/dist 생성
```

### 3. 실행

```sh
npm start        # http://127.0.0.1:4317 에서 허브 + 화면
```

브라우저로 http://127.0.0.1:4317 을 엽니다. 처음 실행하면 `data/`에 DB와 접속 토큰이 생깁니다.

- 허브는 러너(에이전트 세션을 실행하는 프로세스, `127.0.0.1:4318`)가 없으면 따로 띄웁니다. 러너는 허브와 별개 프로세스라 허브를 꺼도 실행 중인 작업이 계속됩니다.
- 허브는 러너에 붙을 때 `data/runner-token`(처음 쓸 때 만들어지고 본인만 읽을 수 있음)을 보여야 합니다. 토큰이 없는 연결은 러너가 끊으므로, 다른 로컬 프로세스가 러너 포트로 작업을 시킬 수 없습니다. 이 확인이 없던 버전에서 올릴 때는 허브와 러너를 함께 재시작합니다(새 허브는 옛 러너에 붙지만, 새 러너는 옛 허브를 받지 않습니다).
- 터미널을 닫아도 허브를 유지하려면 백그라운드로 띄웁니다: `scripts/start-all` (러너와 허브를 띄우고 로그는 `data/runner.log`, `data/hub.log`)

`scripts/`의 스크립트로 띄우고 끄고 다시 띄웁니다. 모두 백그라운드로 띄우고, 포트가 열리거나 닫힐 때까지 기다린 뒤 결과를 알립니다.

| 스크립트 | 하는 일 |
| --- | --- |
| `start-hub`, `stop-hub`, `restart-hub` | 허브만. 실행 중인 작업은 러너에서 계속 돕니다 |
| `start-runner`, `stop-runner`, `restart-runner` | 러너만. 실행 중인 세션이 모두 끝나고, 다음 메시지에서 이전 대화를 이어갑니다. 허브가 떠 있으면 러너를 멈춰도 허브가 10초 안에 다시 띄웁니다 |
| `start-all`, `stop-all`, `restart-all` | 둘 다. 끌 때는 허브를 먼저 꺼서 러너가 다시 뜨지 않게 합니다 |

- 데스크 세션 안에서 `restart-runner`나 `restart-all`을 실행하면 러너를 멈출 때 그 세션도 끝나므로, 스크립트가 스스로 백그라운드로 옮겨 마저 진행합니다(로그 `data/restart.log`).
- `PORT`, `RUNNER_PORT`, `HUB_LOG`, `RUNNER_LOG` 환경 변수로 포트와 로그 위치를 바꿀 수 있습니다.

### 4. 끄기

| 대상 | 방법 |
| --- | --- |
| 허브 | 실행한 터미널에서 `Ctrl+C`, 백그라운드면 `scripts/stop-hub` |
| 러너 | `scripts/stop-runner`. 실행 중인 세션도 함께 끝나며, 다시 띄운 뒤 다음 메시지에서 이전 대화를 resume으로 이어감 |
| 둘 다 | `scripts/stop-all` |

### 5. 업데이트

먼저 받고 다시 빌드합니다.

```sh
git pull
npm install
npm run build
git diff --stat HEAD@{1} -- hub web desktop   # 무엇이 바뀌었는지 확인
```

바뀐 위치에 따라 필요한 만큼만 다시 띄웁니다.

| 바뀐 위치 | 할 일 |
| --- | --- |
| `web/` | 없음. 허브가 새 `web/dist`를 바로 제공하므로 열린 화면(브라우저·앱)에서 `⌘R`로 새로고침만 합니다 |
| `hub/src/` (`runner/`, `config.ts` 제외) | 허브 재시작(`scripts/restart-hub`). 실행 중인 작업은 러너에서 계속 돕니다 |
| `hub/src/runner/` | 실행 중인 작업이 없을 때 러너 재시작: `scripts/restart-runner` |
| `hub/src/config.ts`, `shared/` | 허브와 러너가 함께 쓰므로 둘 다 재시작(러너는 실행 중인 작업이 없을 때). `shared/`는 웹 화면도 쓰므로 `npm run build` 뒤 새로고침 |
| `desktop/` | 데스크톱 앱 재설치 (아래) |
| `package.json`, `package-lock.json` | `npm install` 후 허브 재시작 |

허브 재시작(백그라운드로 띄운 경우):

```sh
pkill -f "node src/index.ts"
nohup npm start >> data/hub.log 2>&1 &
```

데스크톱 앱 업데이트(`desktop/`이 바뀌었을 때만 필요):

```sh
osascript -e 'quit app "Agent Desk"'   # 실행 중인 앱 종료
cd desktop
npm install --workspaces=false
npm run deploy                         # 다시 빌드해 /Applications/Agent Desk.app 교체
open -a "Agent Desk"
```

앱은 허브를 담는 창일 뿐이라 `web/`·`hub/` 변경에는 다시 빌드할 필요가 없습니다. 앱을 다시 빌드해도 허브와 러너는 끊기지 않습니다.

### 6. 데스크톱 앱 (macOS, 선택)

허브 화면을 별도 창으로 띄우고, Finder에서 끌어다 놓은 파일의 실제 경로를 넘겨 줍니다. 앱을 열 때 허브가 꺼져 있으면 빌드한 저장소에서 허브를 띄웁니다.

```sh
cd desktop
npm install --workspaces=false
npm run deploy   # 빌드 후 /Applications/Agent Desk.app 을 교체 (애드혹 서명). 실행 중인 앱은 먼저 종료
```

서명·공증하지 않은 앱이라 처음 실행 때 막히면 Finder에서 우클릭 후 "열기"를 고릅니다. 자세한 동작은 [`desktop/README.md`](desktop/README.md)를 봅니다.

### 개발

- `npm run hub`(파일 변경 시 허브 재시작)와 `npm run web`(Vite, http://127.0.0.1:5173)을 각각 띄웁니다.
- 타입 검사: `npm run typecheck` (hub, web, test)
- 테스트: `npm test` (`node --test`로 `test/**/*.test.ts` 실행. 러너·DB는 가짜 어댑터와 메모리 DB를 써서 서버를 띄우지 않음)
- 실행 데이터(DB, 접속 토큰, 로그, 업로드, 스킬)는 모두 `data/`에 생기며 저장소에는 올리지 않습니다. `data/access-token`과 `data/runner-token`은 다른 사람에게 보이지 않게 둡니다.

### 환경 변수

모두 [hub/src/config.ts](hub/src/config.ts) 한 곳에서 읽습니다. `data/…`로 적은 파일은 DB 파일이 있는 디렉터리를 따라가므로, `AGENT_DESK_DB`만 옮겨도 나머지가 함께 옮겨집니다.

| 변수 | 기본값 | 설명 |
| --- | --- | --- |
| `PORT` / `HOST` | `4317` / `0.0.0.0` | 허브 주소. 네트워크에 열지 않으려면 `HOST=127.0.0.1` |
| `AGENT_DESK_DB` | `data/agent-desk.db` | SQLite DB |
| `AGENT_DESK_TOKEN_FILE` | `data/access-token` | 다른 기기 접속 토큰 (QR 주소의 공용 토큰) |
| `AGENT_DESK_HOSTS` | (없음) | 다른 기기가 허브를 부를 수 있는 이름을 쉼표로 추가 (예: Tailscale MagicDNS 이름). 기본은 이 Mac의 IPv4 주소와 `이름.local`만 받습니다 |
| `AGENT_DESK_UPLOADS` | `data/uploads` | 첨부 파일 저장 위치 |
| `AGENT_DESK_SKILLS_HOME` | `data/desk-plugin` | 데스크 스킬(로컬 Claude Code 플러그인 `desk`) |
| `RUNNER_PORT` | `4318` | 러너 포트 |
| `RUNNER_IDLE_MS` | 30분 | 이 시간 동안 활동이 없는 세션을 닫음. 다음 메시지에서 resume. 상단바의 열린 세션 목록에서 바로 닫을 수도 있음 |
| `RUNNER_LOG` / `RUNNER_PID_FILE` | `data/runner.log` / `data/runner.pid` | 러너 로그와 PID 파일 |
| `RUNNER_TOKEN_FILE` | `data/runner-token` | 허브가 러너에 붙을 때 보이는 토큰 |
| `CODEX_BIN` / `AGY_BIN` | `codex` / `agy` | Codex, Antigravity 실행 파일 |

### 원격 러너에서 작업하기

허브 하나에 로컬 러너와 여러 원격 러너를 함께 연결할 수 있습니다. 기존 `runner:remote` 인스턴스는 허브 하나에 연결합니다. 같은 작업·대화를 여러 허브에서 공동 조작하려면 아래의 별도 `runner:shared` 모드를 사용합니다.

프로젝트는 **실행 계정·머신·디렉터리 하나**에 고정됩니다. 같은 저장소를 로컬과 서버에서 다루려면 서로 다른 프로젝트 이름으로 등록합니다. 경로에는 `ws20:~/project`처럼 호스트 또는 SSH 별칭만 쓸 수 있습니다. 등록 주소가 정확히 일치하면 해당 러너를 선택합니다. 정확히 일치하는 주소가 없으면 `moohnam@ws20`로 등록한 러너도 `ws20`으로 찾으며, 이때 같은 호스트에 여러 계정의 러너가 있으면 실행 계정까지 지정해야 합니다. 선택한 등록 주소를 프로젝트에 저장하므로 이후 다른 계정의 러너를 추가해도 기존 프로젝트의 실행 계정은 바뀌지 않습니다. 미등록·모호한 원격 주소는 로컬에서 실행하지 않고 오류로 알립니다. 호스트 이름은 등록된 표기와 일치해야 하며, 허브가 SSH 설정을 조회하거나 로그인·프로그램 설치를 자동으로 수행하지는 않습니다.

1. 허브 머신의 Agent Desk에서 **설정 → 원격 러너 관리**를 열고 `ws20` 또는 `moohnam@ws20`처럼 실행 위치를 등록합니다. 표시된 연결 토큰은 한 번만 복사할 수 있습니다. 잃어버렸다면 같은 화면에서 재발급합니다. 재발급하면 이전 토큰은 즉시 연결할 수 없지만 실행 중인 원격 작업과 전달 DB는 유지됩니다. 대상 머신의 토큰 파일을 새 값으로 바꾸면 러너를 재시작하지 않고 다시 연결합니다.
2. 대상 머신에서 작업할 계정으로 저장소를 받아 `npm ci`를 실행합니다. Node.js 26 이상과 사용할 CLI가 필요하며, CLI 로그인도 해당 계정에서 미리 끝냅니다. `HOME`이나 `CODEX_HOME`을 허브의 값으로 바꾸거나 인증 파일을 복사하지 않습니다.
3. 복사한 러너 토큰을 대상 머신의 본인만 읽을 수 있는 파일에 저장합니다. 아래처럼 **원격 머신의 Agent Desk 저장소에서** 실행합니다. ID는 등록 화면에 표시된 실제 값으로 바꿉니다. 터미널 종료 후에도 실행하려면 서비스 관리자 또는 `nohup`으로 이 프로세스를 유지합니다.

   ```sh
   AGENT_DESK_HUB_URL=https://desk.example.com \
   AGENT_DESK_RUNNER_ID=remote-등록화면의ID \
   AGENT_DESK_REMOTE_TOKEN_FILE="$HOME/.config/agent-desk/ws20.token" \
   npm run runner:remote
   ```

   원격 러너가 허브에 접속하므로 대상 서버의 러너 포트를 외부에 열 필요가 없습니다. 허브와의 통신은 HTTPS를 사용합니다. SSH 터널을 쓴다면 허브에서 해당 러너의 `POST /api/runners/<id>/exchange`만 전달하는 루프백 릴레이를 먼저 구성합니다. 예를 들어 릴레이가 허브의14318포트에 있으면 **허브 머신에서** `ssh -N -R 127.0.0.1:14317:127.0.0.1:14318 moohnam@ws20`으로 연결하고, 대상 머신의 `AGENT_DESK_HUB_URL=http://127.0.0.1:14317`로 실행할 수 있습니다. 터널의 대상은 허브 전체 API가 아닌 이 러너 전용 릴레이로 제한합니다. 평문 HTTP는 localhost 주소에만 허용합니다. SSH 터널·HTTPS 구성 자체는 자동 생성하지 않습니다.
4. 화면에 `연결됨`이 표시되면 작성창에서 다음처럼 보냅니다. `~`는 원격 실행 계정의 홈으로 해석하며, 원격 디렉터리는 미리 만들어 두어야 합니다. 이후 `@server-work`와 해당 작업의 답글은 계속 같은 머신으로 갑니다.

   ```text
   @server-work:ws20:~/project #codex 이 프로젝트의 테스트를 확인해 주세요
   ```

| 원격 실행 변수 | 의미 |
| --- | --- |
| `AGENT_DESK_HUB_URL` | 대상 러너가 접속할 허브 주소 |
| `AGENT_DESK_RUNNER_ID` | 허브에서 등록한 러너 ID |
| `AGENT_DESK_REMOTE_TOKEN_FILE` | 해당 러너 전용 연결 토큰 파일의 절대 경로 |
| `AGENT_DESK_REMOTE_DB` | 원격 전달 SQLite DB. 기본값은 해당 머신 데이터 디렉터리의 `remote-runner.db` |

**연결이 끊겼을 때:** 원격 러너와 CLI가 살아 있으면 작업은 계속됩니다. 승인이나 질문에 대한 답이 필요해지면 기다립니다. 허브는 새 입력을 DB 대기열에 보관하고, 러너는 결과를 디스크에 보관합니다. 재연결하면 누락된 결과를 순서대로 반영한 뒤 후속 입력을 전달합니다. 오프라인에서 보낸 `#now`도 즉시 전달됐다고 표시하지 않고, 재연결 후 다음 턴에 순서대로 보냅니다. 중단·세션 닫기는 연결 상태를 확인한 뒤 사용합니다. 오프라인 작업을 삭제하면 아직 허브에 남은 시작 명령은 취소하고, 원격에 도착했을 수 있는 세션에는 재연결 후 닫기를 전달합니다.

**전달 보장과 한계:** 허브의 `remote_command`는 상대가 디스크에 수신했다고 확인한 명령만 제거합니다. 러너의 전달 DB는 수신 명령과 미확인 출력을 저장하며, 같은 명령 ID를 다시 받아도 반복 실행하지 않습니다. 허브는 출력의 순번과 적용 결과를 같은 트랜잭션에 기록해 재전송된 글이 중복되지 않도록 합니다. 오프라인 중 발생한 글은 원격에서 기록한 시각을 유지합니다. 수신 확인은 CLI 실행 완료를 뜻하지 않으며, 진행과 완료는 별도 작업 이벤트로 확인합니다.

러너 프로세스가 CLI에 지시를 넘기던 순간 종료되면 외부 실행과 DB 기록을 하나의 트랜잭션으로 묶을 수 없습니다. 실행 여부가 불명확한 명령은 자동 재실행하지 않고 오류로 알립니다. 이미 CLI에 넘긴 지시도 러너 재시작만으로 다시 실행하지 않습니다. 세션이 사라졌다면 오류 상태를 확인하고 새 답글로 이어갑니다. 전달 DB가 삭제되거나 다른 DB로 바뀌면 기존 러너 ID로 무조건 재접속하지 않고 복구를 요구합니다. 같은 DB로 원격 러너 두 개를 동시에 실행할 수 없습니다. 디스크 부족도 자동 삭제로 숨기지 않고 실패로 알립니다. DB는 로컬 디스크에 보관하고 용량을 확보해 주세요.

현재 원격 전달은 인증된 HTTP 교환을 이용하며 정상 상태에서 약 1초마다 묶음으로 교환합니다. 한 번에 최대 64개 출력과 최대 16개 명령을 처리하고, 출력/명령 배치에는 별도 크기 제한이 있습니다. 명시적으로 선택한 `#스킬`의 본문·참조 파일은 입력을 받을 때 내용 버전으로 고정하고, 실행 직전에 대상 머신의 세션 전용 경로에서 같은 버전을 확인합니다. 스킬 묶음은 4 MiB 이하입니다. 업데이트된 원격 러너가 스킬 버전 지원을 알리기 전에는 스킬 태그가 있는 새 입력을 거부하고, 이미 보관한 스킬 입력은 전달하지 않습니다. 일반 입력은 계속 전달합니다. 저장소·일반 파일·CLI 인증은 동기화하지 않습니다. 첨부 파일은 허브에 업로드되므로 원격에 별도로 옮긴 뒤 원격 경로를 입력해야 합니다. 원격 파일 링크를 클릭해 허브 머신의 같은 경로를 잘못 여는 것도 차단합니다.

### 로컬 작업공간의 실행 프로세스 분리(선택 적용)

기본 실행 방식은 그대로 사용할 수 있습니다. 선택 적용 방식에서는 `runner:local` 프로세스가 기존 `AGENT_DESK_DB`의 작업·대화·승인·대기열 원본을 소유하고 기존 4318 러너 데몬에 연결합니다. 허브는 별도 `AGENT_DESK_GATEWAY_DB`에 접속 권한과 공유 작업공간 연결·미전달 입력만 저장하며, 작업 API·MCP·채널·스킬 요청을 로컬 작업공간에 전달합니다. 브라우저의 기존 로컬 작업·세션 ID와 CLI 세션 ID는 바꾸지 않습니다. 기존 공유 러너 연결과 미전달 명령 ID·순서도 게이트웨이 DB로 한 번만 옮깁니다.

1. 전환 전에 기존 허브를 종료하고 4317 포트를 비웁니다. 4318 러너 데몬과 그 CLI 프로세스는 그대로 둡니다. 현재 DB와 데몬 파일을 보존하고, 새 게이트웨이 DB에는 기존 연결 기록이 없어야 합니다. 최초 전환 검사가 실패하면 원본 작업 DB와 연결 기록을 그대로 두고 원인을 해결한 뒤 다시 실행합니다.
2. 기존 `AGENT_DESK_DB`를 지정한 환경에서 진행 중인 세션·승인이 있으면 `npm run runner:local -- --takeover-live`로, 모두 끝났으면 `npm run runner:local`로 시작합니다. 무중단 인수는 기존 데몬에 새 소켓을 만들지 않고 인증된 첫 hello의 활성 세션·승인을 원본 DB와 대조한 뒤에만 작업공간을 열고 소유권을 넘깁니다. 검사가 실패하면 새 연결의 임시 상태를 정리하고 기존 허브 방식으로 복구할 수 있습니다. 기존 데몬 프로토콜에는 별도 출력 ACK가 없으므로 허브 종료와 새 연결 사이의 마지막 출력에 관한 한계는 일반 허브 재시작과 같습니다. 작업공간 API는 `127.0.0.1:4321`에 열립니다. 다른 터미널에서 `npm run runner:local -- grant local-hub /절대경로/local-hub.token`으로 허브 전용 토큰 파일을 만듭니다.
3. 기존 허브 포트에서 아래처럼 허브를 시작합니다. `AGENT_DESK_DB`는 전환 전과 같은 파일을 가리켜야 합니다. `AGENT_DESK_GATEWAY_DB`는 다른 SQLite 파일이어야 합니다. `AGENT_DESK_LOCAL_AUTHORITY_URL`은 생략하면 `http://127.0.0.1:4321/`입니다.

   ```sh
   AGENT_DESK_LOCAL_AUTHORITY_TOKEN_FILE=/절대경로/local-hub.token \
   AGENT_DESK_GATEWAY_DB=/절대경로/gateway.db \
   npm start
   ```

4. 데스크톱 앱처럼 환경변수 없이 허브를 다시 시작하는 경로를 위해 원본 DB와 같은 디렉터리의 `local-mode.json`에도 연결 설정을 저장합니다. 기본 원본 DB를 쓰면 위치는 `data/local-mode.json`입니다. 파일 권한을 `0600`으로 두고 아래 세 값을 **절대 경로**로 지정합니다. 토큰 값은 넣지 않고 토큰 파일의 경로만 적습니다.

   ```json
   {
     "authorityUrl": "http://127.0.0.1:4321/",
     "tokenFile": "/절대경로/local-hub.token",
     "gatewayDbPath": "/절대경로/gateway.db"
   }
   ```

   허브는 명시한 환경변수를 각 값보다 우선하며, 세 환경변수가 모두 있으면 설정 파일을 읽지 않습니다. 다른 위치에 저장할 때는 `AGENT_DESK_LOCAL_MODE_FILE`을 지정합니다. 전환을 마친 뒤 `npm start`와 데스크톱 앱을 각각 재시작해 같은 로컬 작업·세션 ID가 보이는지 확인합니다. 이미 활성화된 로컬 작업공간만 허브가 인증 신원과 원본 DB의 작업공간 ID를 대조한 뒤, 로컬 포트에 프로세스가 없으면 자동 재기동합니다. 첫 `--takeover-live` 인수는 직접 실행해야 하며, 다른 응답·권한 오류·원격 URL에서는 자동 시작하지 않습니다.

로컬 작업공간 자동 재기동이 실패해도 기존 게이트웨이에 인증된 연결이 있고 원본 작업공간 ID·주소·토큰이 모두 일치하면 허브는 오프라인으로 시작합니다. 이때 입력에 202를 응답하고 게이트웨이 DB에 보관하며, 연결이 복구되면 같은 명령 ID로 한 번 전달합니다. 첫 등록, 신원·주소·토큰 불일치, 다른 서비스의 응답, 새 자식 프로세스 종료 미확인 때는 허브를 열지 않습니다. 첫 실행이 수신 시작 전에 실패하면 전환 표시를 남기지 않아 기존 허브로 복구할 수 있습니다. 수신 시작 뒤에는 토큰 파일을 빼고 기존 허브 방식으로 원본 DB를 다시 여는 일을 차단합니다. 게이트웨이 초기화나 연결 기록 이전이 실패하면 원본 DB를 고치거나 삭제하지 않고 원인을 해결해 같은 설정으로 재시도합니다. 기존 일반 `runner:remote`의 작업 원본과 명령 큐는 아래의 별도 원격 이관을 마칠 때까지 로컬 작업공간 DB에 있습니다.

### 기존 일반 원격 러너의 원본 이관

`runner:remote-migrate`는 기존 일반 원격의 프로젝트·작업·세션·이벤트·승인·질문·대기 입력·전달 명령과 스킬을 실행 머신의 원본 DB로 옮깁니다. 작업·세션·이벤트의 기존 ID와 CLI 재개용 세션 ID, 원격 전달 DB의 순번을 유지합니다. 이관은 자동 실행되지 않습니다. 로컬 작업공간 분리와 게이트웨이 준비를 먼저 끝내고, 해당 일반 원격 러너와 대상 공유 러너를 멈춘 뒤 실행합니다. 진행 중인 엔진·승인·질문·다른 작업 질문이 남았거나 전달 DB의 수신 확인을 검증할 수 없으면 이관을 거부합니다. 원본 DB, 원격 전달 DB와 스킬 디렉터리는 완료 확인 전까지 보존합니다.

1. 허브 머신에서 기존 일반 원격 러너 ID를 확인하고, 현재 스킬 홈을 `AGENT_DESK_SKILLS_HOME`으로 지정한 다음 `npm run runner:remote-migrate -- export /절대경로/원본.db remote-기존ID /임시경로/bundle.json`을 실행합니다. 묶음에는 작업 내용과 스킬 파일이 들어 있으므로 본인만 읽을 수 있는 임시 경로에 둡니다. 기존 원격 머신에 묶음을 전달하고, 기존 `AGENT_DESK_REMOTE_DB` 파일을 그대로 유지합니다.
2. 새 공유 작업공간에서는 **가져오기 전에** `npm run runner:shared -- grant 원본허브 /임시경로/origin.token`을 실행해 출력된 `peer_id`를 기록합니다. 이 peer만 이관 스킬을 이후 갱신할 수 있습니다. `npm run runner:remote-migrate -- import /절대경로/공유디렉터리/workspace.db /절대경로/기존remote-runner.db /임시경로/bundle.json 발급된-peer-id`를 실행하고, 이어 `npm run runner:remote-migrate -- verify /절대경로/공유디렉터리/workspace.db /절대경로/기존remote-runner.db /임시경로/bundle.json /임시경로/verified.json`으로 대상 DB·스킬·전달 순번을 다시 확인합니다.
3. 검증 영수증을 허브 머신으로 가져와 게이트웨이를 멈춘 상태에서 `npm run runner:remote-migrate -- commit /절대경로/원본.db remote-기존ID /임시경로/bundle.json /임시경로/committed.json /임시경로/verified.json`을 실행합니다. 원본은 같은 트랜잭션에서 변경되지 않은 스냅숏을 확인하고 해당 러너의 행을 제거하며 이관 표시를 남깁니다. 영수증 파일 생성만 실패했다면 같은 명령을 새 파일 경로로 재실행합니다.
4. 원본 전환 영수증을 원격 머신으로 전달해 `npm run runner:remote-migrate -- activate /절대경로/공유디렉터리/workspace.db remote-기존ID /임시경로/committed.json`을 실행합니다. 기존 등록 주소를 `AGENT_DESK_SHARED_ADDRESS`로, 새 공유 디렉터리를 `AGENT_DESK_SHARED_DIR`로, 기존 전달 DB를 `AGENT_DESK_REMOTE_DB`로, 기존 원격 세션 스킬 홈을 `AGENT_DESK_SKILLS_HOME`으로 지정하고 `AGENT_DESK_REMOTE_MIGRATED_RUNNER_ID=remote-기존ID npm run runner:shared`를 시작합니다. 게이트웨이가 아직 멈춘 상태에서 `npm run runner:remote-migrate -- link /절대경로/원본.db /절대경로/gateway.db remote-기존ID http://127.0.0.1:원격터널포트/ /임시경로/origin.token`으로 대상 신원과 활성화 증거를 확인해 연결·기존 ID 목록을 한 번에 공개한 뒤 게이트웨이를 시작합니다. 이 연결이 없으면 게이트웨이는 이관된 작업을 숨긴 채 시작하지 않고 오류로 중단합니다.

기존 공유 러너에 **작업이 없는** 일반 원격 프로젝트만 합칠 때는 공유 DB·러너 ID·전달 DB·기존 허브 토큰·연결 ID를 유지합니다. 공유 러너를 멈춘 뒤 `merge-import 공유DB 공유전달DB bundle.json 기존일반전달DB`, `merge-verify 공유DB 공유전달DB bundle.json 기존일반전달DB verified.json`, 원본의 위 `commit`, `merge-activate 공유DB 기존일반러너ID committed.json` 순서로 실행합니다. 기존 공유 러너를 다시 시작한 후 `merge-link 원본DB gatewayDB 기존일반러너ID 기존공유linkID`로 과거 ID와 주소를 그 연결에 붙입니다. 기존 일반 원격에 작업·세션·미전달 명령이 있거나 공유 프로젝트의 ID·이름·경로가 충돌하면 합치기를 거부합니다.

대상 활성화 전 취소할 때는 대상의 `abort 대상DB 기존전달DB bundle.json aborted.json` 또는 `merge-abort 공유DB 공유전달DB bundle.json 기존일반전달DB aborted.json`을 실행하고, 원본을 이미 전환했으면 `rollback 원본DB 기존일반러너ID bundle.json committed.json aborted.json`을 실행합니다. 대상 활성화 뒤에는 엔진이 이어졌을 수 있으므로 원본으로 자동 복귀하지 않고 연결과 미전달 입력을 복구합니다. 임시 묶음·토큰·영수증은 양쪽 검증을 마친 뒤 안전하게 정리합니다.

### 같은 러너의 작업을 여러 허브에서 공유하기

`runner:shared`는 실행 머신에 작업·대화·승인·대기열의 원본 DB와 엔진 러너 하나를 함께 둡니다. 각 허브는 같은 작업공간에 접속하고, 로컬·일반 원격·공유 작업을 기존 컬럼에 함께 표시합니다. 우측 상단의 **실행 위치 및 전달 내역**에서 표시할 작업을 좁히거나 미전달 입력을 확인할 수 있습니다. 표시 필터는 새 작업의 실행 대상을 바꾸지 않습니다.

로컬·일반 원격·공유 러너는 같은 엔진 실행 코드를 사용하며 **Claude·Codex·Antigravity(agy)** 를 지원합니다. `#claude`, `#codex`, `#agy`와 모델·effort 태그를 같은 방식으로 사용합니다. 해당 머신에서 러너를 실행하는 계정에 사용할 CLI와 로그인이 준비돼 있어야 하며, 서비스의 `PATH` 또는 `CODEX_BIN`·`AGY_BIN`으로 실행 파일을 찾을 수 있어야 합니다. 지원 엔진 목록은 어댑터 지원 여부이며 CLI 설치·로그인 성공을 뜻하지 않습니다. agy의 도구 승인에는 해당 계정의 PreToolUse 훅 연동도 필요합니다. 설치·로그인·훅 설정은 다른 머신에서 자동 복사하지 않습니다.

기존 `runner:remote`의 DB나 작업은 공유 모드를 시작하는 것만으로 이전되지 않습니다. 기존 작업을 이어받으려면 위의 검증·원본 전환·대상 활성화 절차를 순서대로 수행해야 합니다. 새 공유 디렉터리에서 독립적으로 시작한 작업은 기존 일반 원격 작업과 별개입니다.

1. 실행 머신에서 Node.js 26 이상과 의존성을 준비하고, 공유 데이터 디렉터리와 고정된 실행 주소를 지정합니다. 디렉터리는 로컬 디스크에 두고 CLI 로그인 계정의 홈은 유지합니다.

   ```sh
   export AGENT_DESK_SHARED_DIR="$HOME/.local/share/agent-desk/shared"
   export AGENT_DESK_SHARED_ADDRESS=dbteam@srv19
   export AGENT_DESK_SHARED_PORT=4321
   npm run runner:shared
   ```

   공유 서버는 **127.0.0.1에만** 열립니다. 기본 4321은 예약·무충돌을 보장하는 번호가 아니므로 사용 중이면 바꿉니다. 서비스 관리자로 실행하면 허브 연결이 끊겨도 엔진과 기록이 유지됩니다. 공유 러너 프로세스 자체가 종료되면 살아 있는 엔진까지 유지한다는 의미는 아닙니다. 정상 종료 후 재시작하면 진행 중이던 턴은 중단 사실을 기록하고, 대기 중인 입력은 보존하여 순서대로 전달합니다. 중단된 턴의 원래 지시를 자동 재실행하지는 않습니다. 같은 공유 디렉터리에 실행 프로세스를 두 개 띄우면 거부합니다.

2. 같은 머신의 다른 터미널에서 **동일한 `AGENT_DESK_SHARED_DIR`**을 지정하고 허브마다 토큰을 따로 발급합니다. 토큰 값은 출력하지 않고 지정한 새 파일(권한600)에 저장합니다. 기존 파일은 덮어쓰지 않습니다.

   ```sh
   npm run runner:shared -- grant my-mac /절대경로/my-mac.token
   npm run runner:shared -- grant another-hub /절대경로/another-hub.token
   npm run runner:shared -- peers
   # 특정 허브의 권한 취소. 이미 열린 스트림도 다음 확인 때 종료됩니다.
   npm run runner:shared -- revoke 허브ID
   ```

   토큰을 받은 허브는 해당 공유 작업공간의 전체 작업을 조회·생성·입력·승인·중단·삭제할 수 있습니다. 읽기 전용 권한이나 사용자별 프로젝트 권한은 아직 없습니다. 토큰은 각 허브 DB에 저장하고 화면/API 목록에는 반환하지 않습니다. 승인 응답 등 미전달 입력도 DB에 있으므로 데이터 디렉터리 접근을 실행 계정으로 제한합니다.

3. **각 허브 머신에서** 별도의 SSH 터널을 연결합니다. 예를 들어 `ssh -N -L 127.0.0.1:15321:127.0.0.1:4321 dbteam@srv19`로 연결합니다. 허브의 **설정 → 원격 러너 관리 → 같은 작업을 여러 허브에서 공유**에서 이름, `http://127.0.0.1:15321`, 그 허브용 토큰을 등록합니다. 원격 HTTPS 프록시를 준비했다면 경로 없는 HTTPS 주소도 사용할 수 있습니다. 등록할 때 러너의 실제 작업공간 ID를 확인하고 고정하므로 다른 DB에 잘못 연결되어 미전달 입력을 실행하는 것을 막습니다.
4. 새 지시의 실행 대상으로 해당 공유 러너를 선택하고 `@shared-test:dbteam@srv19:~/test-proj #codex 테스트 프로젝트`처럼 시작합니다. `#claude`나 `#agy`도 같은 방식으로 지정합니다. 다른 허브에서도 같은 프로젝트·작업·대화가 보이며 같은 승인과 대기열을 조작합니다. 프로젝트 디렉터리는 실행 머신에 미리 만들어야 합니다.

허브를 연결하거나 다시 연결하면 스킬 이름·내용 지문을 비교해 달라진 스킬 파일만 실행 머신의 해당 허브 전용 캐시에 보냅니다. 연결 중에도 약 15초마다 확인하므로 스킬 관리 화면의 수정뿐 아니라 파일을 직접 고친 내용도 반영됩니다. 다른 허브의 동명 스킬은 별도 캐시에 둡니다. 메시지에 명시한 `#스킬`과 조건부 하위 참조의 본문·필요 파일은 **입력을 접수할 때** 고정합니다. 대기 중에 원본 스킬을 바꿔도 그 입력은 이전 버전을 사용합니다. 정상 전달에서는 이름과 내용 지문만 보내고, 실행 직전 캐시가 없거나 지문이 다르면 고정한 파일을 같은 명령 ID의 준비 단계에서 복구한 뒤 실행합니다. 수신 확인이 사라져 재전송해도 같은 명령을 두 번 실행하지 않습니다.

해당 허브에 등록된 스킬의 명시적 `#스킬이름`만 선택하며, 없는 태그는 원문에 남깁니다. 하위 참조 파일은 준비만 하고 조건에 맞을 때 에이전트가 읽습니다. 엔진 자체의 스킬 자동 선택은 이 명시적 선택과 별개이며 허브 전용 캐시의 파일이 자동 등록되지는 않습니다. 구형 공유 러너는 스킬 태그가 있는 입력을 실행하지 않고 업데이트가 필요하다는 오류와 원문을 전달 내역에 남깁니다. 일반 입력은 계속 처리합니다.

**연결 단절과 중복 처리:** 각 허브는 입력을 자신의 SQLite에 먼저 기록합니다. 러너가 받을 수 없으면 작성창을 비우고 ‘허브에 보관’ 안내를 표시하며 상단 **전달 내역**에 남깁니다. 연결이 복구되면 허브별 입력 순서대로 전달하며, 허브 사이의 동시 입력 순서는 러너가 실제 수락한 순서입니다. 공유 명령 ID·내용의 해시·처리 결과와 엔진 명령을 원본 DB의 같은 트랜잭션에 기록합니다. 같은 ID로 재전송하면 저장한 결과를 돌려주고 다시 실행하지 않습니다. 서로 다른 승인 응답이 경합하면 먼저 처리한 것만 적용하고 나중 응답은 실패 내역에 남깁니다. 토큰이 취소되면 미전달 입력을 버리지 않고 보관하므로 새 토큰으로 연결을 갱신할 수 있습니다. 전달 대기는 허브 전체에서 최대1,000건/32MiB이며 한도에 도달하면 새 입력을 거부합니다.

**범위:** 작업 생성·대화·검색·과거 기록·승인·대기열·중단·세션 닫기·작업 삭제가 공유됩니다. 연결된 작업공간 사이의 `desk_request` 질문과 답변도 게이트웨이에서 요청 ID와 전달 상태를 보관해 기존 승인 절차에 따라 중계합니다. 허브 머신에서 공유 작업의 파일 링크를 누르면 실행 머신의 프로젝트 폴더 또는 임시 폴더에 있는 단일 파일(최대 50 MiB)을 허브 머신의 임시 폴더로 복사해 기본 앱으로 엽니다. 실행 가능한 파일은 Finder에 표시만 합니다. 복사본은 최대 24시간 보관하고, 허브 종료 시 지웁니다. HTML 파일이 참조하는 상대 경로의 CSS·이미지 등은 함께 복사하지 않습니다. 파일 업로드, 채널 관리, 스킬 편집, 사용량 조회는 이번 공유 API 범위에 포함하지 않습니다. 실행 머신의 파일은 그 머신에 옮긴 뒤 경로로 지시합니다. UI 연결이 끊긴 동안 이미 열린 내용은 남지만, 화면을 새로 열거나 과거 기록을 조회하려면 다시 연결돼야 합니다. 엔진 실행 도중 프로세스가 종료되어 수행 여부를 확정할 수 없는 명령은 기존 원격 전달과 같이 자동 재실행하지 않고 오류로 남깁니다.

`desk_request`는 사용자가 대상을 @로 지정했거나 승인한 뒤, 연결된 Codex·Claude의 실행 중인 턴에 질문을 전달합니다. 대상은 요청 ID와 자신의 세션 ID를 넣어 `desk_reply`로 답해야 하며, 연결이 끊겼거나 실행 중 삽입을 지원하지 않는 엔진의 질문은 대기열에 보관됩니다. Antigravity 작업은 `desk_reply` 자동 연결을 지원하지 않으므로 문의 대상으로 선택할 수 없습니다. 최초 호출은 기본 15초 안에 답이 없으면 요청 ID를 돌려주므로 같은 질문을 다시 만들지 말고 `desk_wait_answer`로 기다립니다. 어떤 턴이든 명시 회신이 없으면 그 턴의 최종 응답을 답으로 보내지 않고 실패로 끝냅니다. 데스크가 시작한 Codex·Claude 세션에는 데스크 MCP를 별도로 연결하며, 원격 공유 러너의 이 연결은 자기 작업공간의 문의와 수신한 다른 작업공간 문의에 답할 수 있습니다. 기존 일반 원격 러너는 MCP를 수동으로 설정한 경우에만 해당 도구를 사용할 수 있습니다. 원격 공유 러너에서 다른 작업공간으로 새 문의를 시작하려면 게이트웨이 MCP 연결이 따로 필요합니다. 이미 실행 중인 세션이 새 MCP 도구 목록을 다시 읽는지는 보장되지 않으므로, 그 세션에서 `desk_reply`가 보이지 않으면 새로 시작한 세션에서 사용해야 합니다. 터미널에서 붙은 작업에 사용자 메시지 이벤트가 없으면 같은 대상·본문의 완료된 문의도 재호출 시 재사용되므로 새 문의에는 본문을 구분해 주세요.

### 다른 기기에서 열기

이 Mac에서 `localhost`·`127.0.0.1`로 접속할 때는 토큰이 필요 없습니다. 다른 기기(PC, 폰)는 기기마다 따로 받은 토큰으로 접속합니다.

1. 다른 기기의 브라우저로 `http://<Mac 주소>:4317`을 엽니다(주소는 상단 **다른 기기 연결** 창에 나옴). 이름을 확인하고 **접속 요청 보내기**를 누릅니다.
2. 이 Mac의 데스크 화면 오른쪽 위에 요청 카드가 뜹니다(알림을 켰으면 OS 알림도). 두 화면의 4자리 코드가 같은지 확인하고 **허용**을 누르면 그 기기가 연결됩니다. 허용·거절은 이 Mac에서만 할 수 있고, 답이 없는 요청은 10분 뒤 사라집니다.
3. **다른 기기 연결** 창의 **연결한 기기**에서 기기마다 연결 상태(연결 중·마지막 접속·주소)를 보고, 이름을 눌러 바꾸고, **끊기**로 그 기기의 토큰을 지웁니다. 끊으면 열려 있던 화면도 바로 끊기고, 그 기기는 다시 요청해야 합니다. 다만 QR로 연결했던 기기는 QR 주소를 알고 있으므로, 그런 기기를 막으려면 같은 창의 **QR 토큰 바꾸기**도 누릅니다.

다른 기기는 이 Mac의 IP 주소나 `이름.local`로만 접속할 수 있습니다. 다른 도메인 이름으로 온 요청은 거절합니다(웹 페이지가 자기 도메인을 이 Mac으로 돌려 기기처럼 행세하는 것을 막기 위해서). Tailscale 이름처럼 다른 이름을 쓰려면 `AGENT_DESK_HOSTS`에 넣습니다.

같은 창의 QR 코드(허브 시작 로그에도 나옴)를 스캔하면 요청 없이 바로 연결되고, 그 기기도 목록에 들어갑니다. QR에는 공용 토큰(`data/access-token`)이 들어 있습니다. **QR 토큰 바꾸기**를 누르면 QR이 바뀌고 이미 연결한 기기는 그대로 남습니다. 공용 토큰 쿠키로 접속하던 기존 기기는 다음에 페이지를 열 때 자기 토큰으로 바뀝니다. MCP 클라이언트의 `Authorization: Bearer`는 공용 토큰을 그대로 씁니다. 기기 토큰은 해시로만 `data/devices.json`에 저장합니다. 로컬 파일 링크 열기는 Mac에서만 동작합니다.

## 기본 사용법

1. `npm start`로 허브를 띄우고 http://127.0.0.1:4317 (또는 데스크톱 앱)을 엽니다.
2. `i`로 작성 서랍을 열고 `@프로젝트이름:/작업/디렉터리 할 일`처럼 첫 작업을 보냅니다. 프로젝트가 등록되고 새 작업이 시작됩니다. 이후에는 `@프로젝트이름`만 쓰면 됩니다(`Tab`으로 완성).
3. 작업 글이 컬럼에 실시간으로 올라옵니다. `j`/`k`로 글을 고르고 `Enter`로 스레드를 열어 전체 흐름을 봅니다.
4. 도구 승인 요청이나 질문이 오면 글에서 바로 누르거나 `y`/`n`으로 답합니다. 여러 작업의 대기 건은 `a`(응답 대기열)에서 한꺼번에 처리합니다.
5. 스레드에서 `r`로 후속 지시를 보냅니다. 실행 중에 보낸 메시지는 대기열에 쌓였다가 턴이 끝나면 보내집니다.
6. `c`로 컬럼을 추가해 프로젝트·작업·상태별로 나눠 봅니다. 스레드에서 `p`를 누르면 그 작업을 컬럼으로 고정합니다.

### 스레드의 글을 왼쪽에 고정하기

스레드를 오른쪽 분할 화면으로 연 뒤 글 머리의 책갈피 버튼을 누르면, 왼쪽에 **고정한 글** 창이 열리고 선택한 순서대로 글이 쌓입니다. 현재 열린 스레드에서 고른 글만 표시하며, 선택은 스레드별로 이 기기에 기억합니다. 오래된 글도 원문을 불러옵니다. 각 카드에서 원문으로 이동하거나 고정을 해제할 수 있고, 창만 닫으면 선택은 유지한 채 왼쪽 컬럼으로 돌아갑니다. 같은 스레드에서 다시 열면 읽던 내용과 스크롤 위치를 유지합니다. 스레드 머리의 고정 글 창 버튼으로 다시 엽니다. 컬럼 모드와 휴대폰·좁은 화면에서는 이 창을 표시하지 않습니다.

### 대상 지정 (`@`)

| 입력 | 의미 |
| --- | --- |
| `@프로젝트:/절대/경로` | 프로젝트를 등록(이미 있으면 재사용)하고 새 작업 시작. 디렉터리가 없으면 만들고 스레드에 알림 |
| `@프로젝트:서버:~/경로` | 등록한 원격 러너에서 새 작업 시작. 같은 호스트에 러너가 여러 개일 때만 사용자@서버로 계정 지정. 해당 머신에 디렉터리가 있어야 함 |
| `@프로젝트` | 그 프로젝트의 가장 최근 작업에 이어서 보내기 |
| `@프로젝트#2` | 그 프로젝트의 2번 작업에 보내기 (번호는 스레드 머리에 표시) |

스레드에서 답글로 보낼 때는 `@`가 필요 없습니다.

### 태그 (`#`)

태그는 메시지 어디에 써도 되고, 보낼 때 본문에서 빠집니다. 모르는 태그는 글자 그대로 남습니다. `#`을 치면 완성 목록이 뜹니다.

| 태그 | 의미 | 유지 범위 |
| --- | --- | --- |
| `#ask` / `#auto` | 도구 실행을 매번 확인(기본) / 자동 승인 | 다른 쪽 태그를 쓸 때까지 |
| `#claude` / `#codex` | 새 작업의 엔진 (기본 Claude). 기존 작업은 엔진을 바꾸지 않음 | 작업 |
| `#opus` `#sonnet` `#haiku` | Claude 모델 | 작업 (다른 모델 태그까지) |
| `#sol` `#astra` `#terra` `#luna` | Codex 모델 계열(그 계열의 최신 버전) | 작업 (다른 모델 태그까지) |
| `#low` `#medium` `#high` `#xhigh` `#max` | reasoning effort. 모델이 지원하지 않는 단계면 가장 가까운 단계로. `#ultra`는 Codex 전용 | 작업 |
| `#later` / `#now` | 실행 중일 때 지금 턴이 끝난 뒤 보내기(기본) / 지금 턴에 끼워 넣기 | 이 메시지 |
| `#new` | 같은 프로젝트에서 새 작업 시작 (이전 대화 없이) | 이 메시지 |
| `#fork` | 지금까지의 대화를 복사해 이어가는 새 작업 (원래 작업과 동시에 진행) | 이 메시지 |
| `#스킬이름` | 그 데스크 스킬을 이 메시지에만 적용 | 이 메시지 |

모델 태그는 새 작업의 엔진도 정합니다(`#sol`이면 Codex). 태그가 없는 새 작업은 데스크의 기본 모델 설정(상단 모델 버튼)을 따릅니다.

예:

```text
@agent-desk:/Users/me/src/agent-desk #codex #high 검색 컬럼에 날짜 필터를 추가해줘
@agent-desk #auto 린트 오류를 모두 고쳐줘
@agent-desk#2 #now 테스트는 건너뛰고 빌드만 확인해
@agent-desk #fork 같은 내용을 다른 방식으로 구현해봐
@agent-desk #new #review 최근 변경을 리뷰해줘   # review라는 데스크 스킬이 있을 때
```

`⌘ Enter`로 보냅니다. 입력란에서는 Emacs 식 커서 이동·삭제 키(Ctrl+A/E/F/B/N/P/D/H/K/W, Alt+F/B/D 등)를 씁니다.

### 주요 단축키

| 키 | 동작 |
| --- | --- |
| `j` / `k` | 아래 / 위 글 |
| `J` / `K` | 다음 / 이전 작업의 글로 (스레드에서는 다음 / 이전 내 글로) |
| `Ctrl Shift J` / `K` | 다음 / 이전 작업의 내 지시 글로 (같은 작업이 이어지면 맨 위 지시 하나만) |
| `h` / `l` | 왼쪽 / 오른쪽 컬럼 |
| `gg` / `G` / `gr` | 맨 위 / 맨 아래 / 전체 컬럼의 가장 최근 글 |
| `gh` / `gl` | 맨 왼쪽 / 맨 오른쪽 컬럼으로 |
| `Enter` / `q` | 스레드 열기 / 닫기 |
| `Esc` | 열린 창(설정·열린 세션 등) 닫기, 작성 서랍에서는 서랍 닫기 (쓰던 내용은 유지) |
| `f` | 스레드를 화면 오른쪽 절반 / 덱의 컬럼으로 보기 (절반일 때는 덱이 왼쪽에서 따로 스크롤되고, 경계선을 끌어 30–70%로 조절, 더블클릭은 절반. 화면이 작으면 스레드를 560px 이상으로 넓히고, 덱이 420px보다 좁아지면 스레드가 작업 공간 전체를 덮습니다. 덮을 때는 포커스가 덱으로 가면 스레드가 비켜나고 `t`로 다시 나옵니다) |
| `t` | 스레드로 가기 / 이전 컬럼으로 돌아가기 (절반일 때 `h`/`l`은 스레드를 건너뛰고, 스레드에서 누르면 이전 컬럼으로) |
| `r` / `i` | 답글 쓰기 (글 미선택 시 컬럼의 작업 또는 최신 글 기준) / 새 작업 |
| `y` / `n` / `s` | 승인 / 거절 / 작업 중단 |
| `a` | 응답 대기열 |
| `F1` – `F4` | 뷰 전환: 내 컬럼 / 프로젝트별 / 작업별 / 상태 보드 |
| `v` | 현재 컬럼을 작업별로 묶어 보기 (작업마다 최근 글 하나) |
| `/` | 검색 |
| 종 버튼 | 알림 켜기·끄기: 데스크를 보고 있지 않을 때 승인 요청·질문·작업 끝남·오류를 OS 알림으로 (데스크톱 앱, 또는 `localhost`나 https로 연 PC 브라우저. 알림 제목은 종류와 작업 이름, 본문은 에이전트의 최근 메시지나 질문(잠금 화면에서 본문을 숨기려면 macOS 설정 > 알림 > 미리보기 보기를 '잠금 해제 시'로), 한꺼번에 여러 건이면 한 번으로 묶음. 같은 브라우저의 창끼리만 중복을 막으므로 앱과 브라우저를 함께 켜면 둘 다 알릴 수 있음) |
| `;` | 컬럼 찾기: 지금 뷰의 모든 컬럼을 이름 일부로 검색하고 이동 (아직 표시하지 않은 컬럼 포함, ↑↓ 또는 Ctrl+N/P로 고르고 Enter) |
| `c` / `e` / `p` / `D D` | 컬럼 추가 / 편집 / 작업 고정 / 삭제 |
| `H` / `L`, `<` / `>` | 컬럼 옮기기, 폭 조절 |
| `?` | 전체 단축키 도움말 |

## 기능

- **도표**: 답변의 Mermaid 코드 블록을 도표로 표시합니다(기본 `theme: redux-color`, `look: handDrawn`). 색상을 지정하지 않은 손그림 순서도 노드에는 팔레트 색상을 차례로 적용합니다. 도표 원문의 YAML `config`로 테마·스타일을 바꾸고 `classDef`·`style`로 노드 색상을 지정할 수 있습니다. 직접 지정한 스타일과 `themeVariables`·`themeCSS`를 우선합니다. 크게 보기와 원문 보기를 제공하며, 문법 오류가 있으면 원문을 표시합니다.

  도표별 설정은 다음처럼 코드 블록 안에 작성합니다. `config`를 생략하면 기본값을 사용합니다.

  ```mermaid
  ---
  config:
    theme: forest
    look: classic
  ---
  graph LR
    A[클라이언트] --> B[(데이터베이스)]
  ```

- **작업**: 프로젝트(작업 디렉터리)마다 Claude Code 또는 Codex 세션을 띄우고, 후속 지시·중단·resume을 합니다. 작업마다 `프로젝트#번호`가 붙습니다.
- **승인과 질문**: 도구 실행 승인/거절, 에이전트 질문(선택지 포함)에 답하기. 좌측 하단의 **응답 대기** 버튼이나 `a`로 작은 응답 패널을 열고, `j/k`로 이동하며 승인·거절하거나 스레드에서 답합니다. `Esc` 또는 `a`로 접습니다. 선택지 질문이 기다리는 동안 그 작업에 답글을 보내면 선택지 대신 그 답글을 답으로 씁니다(**답하지 않기**를 누르며 답글 내용을 전한 것과 같음. Codex는 각 질문의 답으로 넣음). 카드에는 "답글로 답함"으로 남습니다.
- **메시지 대기열**: 실행 중에 보낸 메시지는 턴이 끝난 뒤 보내며(`#later`, 기본), `#now`는 지금 턴에 끼워 넣습니다. 스레드 답글을 `⌘Enter`(또는 `Ctrl Enter`)로 대기열에 넣은 뒤 입력을 수정하지 않고 같은 입력란에서 다시 누르면, 방금 넣은 메시지 하나만 지금 보냅니다. 대기 중인 메시지는 수정·순서 변경·바로 보내기가 됩니다.
- **컬럼**: 작업·프로젝트·종류·상태·검색어로 컬럼을 구성하고, 이름 변경(제목 더블클릭)·폭 조절·순서 변경을 합니다. 설정은 브라우저에 저장합니다. 모든 뷰에서 진입 시 내용이 있는 가장 왼쪽 컬럼을 기본 선택하며, 사용자가 직접 선택한 뒤에는 자동으로 옮기지 않습니다.
- **뷰 (F1–F4)**: 상단 탭이나 `F1`–`F4`로 바꿉니다. **F1 내 컬럼**은 직접 구성한 컬럼, **F2 프로젝트**는 프로젝트마다 컬럼 하나(처음 12개, 마지막 컬럼에서 `l`이나 끝의 "이전 프로젝트" 버튼으로 12개씩 더), **F3 작업**은 작업마다 컬럼 하나(진행 중인 작업은 항상 넣고 나머지는 최근 활동순, 컬럼도 늘 최근 활동순, 처음 12개이며 마지막 컬럼에서 `l`이나 끝의 "이전 작업" 버튼으로 12개씩 더), **F4 상태**는 응답 대기 · 실행 중 · 멈춤·오류 · 작성 중 · 완료 컬럼에 작업을 하나씩 모아 보여 줍니다. 작업은 한 컬럼에만 들어가며, 여러 조건에 맞으면 응답 대기 > 멈춤·오류 > 작성 중 > 실행 중 > 완료 순으로 앞선 곳에 둡니다. `h`/`l`로 컬럼을 옮길 때 빈 상태 컬럼은 건너뜁니다. F2–F4는 작업에 따라 자동으로 구성되어 폭과 묶어 보기만 바꿀 수 있고(F2는 `H`/`L`로 컬럼 순서도 바꿀 수 있습니다. 옮긴 순서는 뷰마다 기억하고, 새 프로젝트·작업은 자동 순서 자리에 들어갑니다. 컬럼 메뉴에서 이름순이나 만든 순(오래된 것부터, 새 컬럼은 오른쪽 끝)으로 정렬하면 새 컬럼에도 그 정렬이 계속 적용되고, "자동 순서"로 되돌릴 수 있습니다), 그곳에서 컬럼으로 고정·나누기·검색 저장을 하면 F1에 추가됩니다. 한 번 본 뷰의 글은 기억해 두어 다시 바꿀 때 바로 보이고, 최신 글만 뒤에서 받아 합칩니다. 마지막으로 본 뷰는 기억합니다. macOS 키보드에서는 `fn`과 함께 누르거나 "F1, F2 등의 키를 표준 기능 키로 사용"을 켜야 할 수 있습니다.
- **작업 구분**: 글 묶음 왼쪽 띠는 프로젝트 색에 작업 번호별 색조를 더해 같은 프로젝트의 작업끼리도 구분되고, 머리줄에 `#번호` 배지가 붙습니다. 컬럼 메뉴(`⋯`)의 **작업별로 묶어 보기**(`v`)는 작업마다 가장 최근 글 하나만 보여 주고, **작업별 컬럼으로 나누기**는 그 컬럼의 작업을 실행 중인 것부터 최대 6개까지 각각의 컬럼으로 만듭니다.
- **초안 보존**: 답글, 질문에 직접 입력하는 답, 작성 서랍에 쓰다 만 내용은 이 기기(localStorage)에 작업별로 저장되어 다른 스레드에 다녀오거나 새로고침해도 남습니다. 답글 초안이 있는 작업은 "✎ 작성 중"으로 표시되고(질문·승인에 쓰다 만 답은 저장만 하고, 그 작업은 응답 대기에 그대로 둡니다), 상단 **작성 중** 칩을 누르면 그 스레드를 차례로 열어 입력란에 커서를 둡니다. 보내면 초안은 지워집니다. 비밀번호 같은 비밀 답은 저장하지 않습니다.
- **검색**: `/`로 검색 컬럼을 열고 `#project:`, `#status:`, `#kind:`, `#task:` 필터를 씁니다. 스레드를 선택한 상태에서는 해당 작업의 `#task:` 필터를 자동으로 넣어 아직 불러오지 않은 과거 대화까지 검색합니다. 필터를 지우면 전체 범위로 검색할 수 있습니다. 결과의 글에서 Enter를 누르면 원래 스레드의 해당 위치로 이동합니다.
- **첨부**: 파일·이미지를 끌어다 놓거나 붙여 넣으면 `data/uploads`에 저장해 경로를 넘깁니다. 폰에서도 올릴 수 있습니다.
- **스킬**: 상단 스킬 버튼에서 데스크 스킬을 만들고 고칩니다. 메시지에 `#스킬이름`을 쓰면 그 메시지에만 적용합니다. 스킬 본문에도 `쉬운 설명이 필요하면 #eli5 를 읽고 적용한다`처럼 다른 데스크 스킬을 참조할 수 있습니다. 하위 스킬의 파일은 준비해 두지만 조건에 맞을 때 에이전트가 읽습니다. 메시지에서 허브에 없는 `#태그`는 원문에 남기고, 스킬 문서의 없는 참조는 에이전트가 알립니다. 문서 안의 `#auto` 같은 제어 태그는 설정을 바꾸지 않습니다. 스킬 태그를 명시한 입력은 접수 시점의 내용을 고정하며, 업데이트된 러너에서만 실행합니다.
- **터미널 세션 붙이기(MCP)**: 허브의 `/mcp`(Streamable HTTP)를 `agent-desk` MCP 서버로 등록하면, 터미널에서 돌던 Claude Code·Codex 세션이 `desk_attach`, `desk_post`, `desk_checkpoint`, `desk_ask`, `desk_finish`로 데스크에 진행을 올리고 질문할 수 있습니다.

  ```sh
  claude mcp add --scope user --transport http agent-desk http://127.0.0.1:4317/mcp
  ```

  Codex는 `~/.codex/config.toml`에 다음을 추가합니다.

  ```toml
  [mcp_servers.agent-desk]
  url = "http://127.0.0.1:4317/mcp"
  ```

- **터미널 세션 넘기기(`desk_handoff`)**: 터미널에서 하던 Claude Code·Codex 세션에 "데스크로 넘겨"라고 하면, 에이전트가 자기 세션 ID(`$CLAUDE_CODE_SESSION_ID`, `$CODEX_THREAD_ID`)로 `desk_handoff`를 호출합니다. 허브가 그 세션 파일(`~/.claude/projects`, `~/.codex/sessions`)을 찾아 같은 대화를 이어 가는 데스크 작업을 만들고, 지금까지 주고받은 말을 스레드에 옮깁니다. 도구 호출은 이름만 "도구 N회"로 요약하고, 가져온 기록은 전체 피드에는 띄우지 않고 그 작업의 스레드와 작업 컬럼에서만 보입니다. 이후 답글은 원래 대화의 맥락을 그대로 가진 채 이어집니다. 세션 ID가 없으면 그 디렉터리에서 가장 최근에 쓰인 세션을 고릅니다. `desk_attach`로 붙어 있던 작업이면 `task_id`를 넘겨 그 작업을 데스크 작업으로 바꿉니다(이때는 기록을 다시 옮기지 않습니다). 넘긴 뒤에는 터미널 세션을 종료하세요. 같은 대화를 양쪽에서 이어 가면 기록이 갈라집니다. 모델·effort는 데스크 기본값으로 이어지며 `#모델` 태그로 바꿀 수 있습니다.

### 읽기 전용 채널

**RSS·Atom을 처음 추가할 때**

1. 상단 설정(톱니바퀴) → **읽기 전용 채널 관리 · 봇 알림 / RSS·Atom**을 엽니다. PC에서는 F1에서 `c` → 같은 채널 관리 버튼으로도 들어갈 수 있습니다.
2. 이름을 입력하고 종류를 **RSS·Atom 구독**으로 고릅니다.
3. 구독 URL에 사이트가 제공하는 RSS·Atom 피드 주소를 입력합니다. 일반 홈페이지 주소와 다를 수 있으며, 예시 형식은 `https://example.com/feed.xml`입니다.
4. **채널 추가** → 아래 채널 목록의 **컬럼에서 열기**를 누르면 F1에 읽기 전용 컬럼이 생깁니다. 글은 자동으로 수집하며 바로 확인하려면 **지금 갱신**을 누릅니다.

**일반 작업 컬럼이나 이미 등록한 채널을 추가할 때**

1. F1 **내 컬럼**에서 `c` 또는 **컬럼 추가**를 누릅니다.
2. **내용**에서 **에이전트 작업** 또는 등록한 읽기 전용 채널을 고릅니다. 작업 컬럼은 프로젝트·작업·종류·상태·검색어 필터를 정하며, 선택하지 않은 필터는 전체를 뜻합니다.
3. 제목을 입력하고 **추가**를 누릅니다. 제목을 비우면 선택한 내용에 맞춰 정합니다.

휴대폰에서는 설정 → 채널 관리 → **컬럼에서 열기**로 읽고 **전체 피드**로 돌아갑니다. 컬럼을 닫아도 구독과 글은 남아 다시 열 수 있습니다. 채널 관리에서 **삭제**하면 구독과 저장된 글을 함께 삭제합니다.

- 채널에서는 `/`로 해당 채널을 검색하고, `j/k`로 이동하며, `o`로 긴 글을 펼치고 Enter로 원문을 엽니다. **여기까지 읽음**(`m`)·**모두 읽음**은 같은 허브의 모든 기기가 공유합니다.
- 원본 글은 일반 텍스트로 표시합니다. RSS·Atom의 HTML 본문은 텍스트로 정리하며, 원문 링크를 따로 제공합니다. 원본 수집·읽음 상태는 에이전트 작업·세션과 분리됩니다. 사용자가 질문하면 채널별 대화 작업을 하나 만들어 연결합니다.
- 피드는 기본 5분 간격으로 확인하고 ETag/Last-Modified를 사용합니다. 실패하면 간격을 늘려 재시도하며 관리 창에 최근 오류를 표시합니다. **지금 갱신**과 일시 중지를 지원합니다. 공개 HTTP(S) URL만 구독할 수 있고 내부망·인증정보가 포함된 URL은 지원하지 않습니다.
- 한 피드 응답은 2 MiB, 항목 본문은 64 KiB까지 처리합니다. 화면은 최근 일부만 메모리에 두고 이전 글을 페이지로 읽습니다. 수집 중단이나 원문 피드에서 글이 사라져도 저장한 글을 자동 삭제하지 않습니다. 관리 창에서 채널을 삭제하면 그 채널의 글도 삭제됩니다.
- 최초 수집량은 RSS 제공처가 현재 보내는 글 수입니다. 예를 들어 최근 30개를 제공하면 처음에는 30개만 생기며, 이후 새 글을 누적합니다. **이전 글 더 보기**는 데스크에 저장된 기록을 불러옵니다. 사이트의 전체 과거 글을 가져오는 기능은 아닙니다.

**채널에서 에이전트와 대화할 때**

1. 한 글의 **이 글로 질문**을 누르거나, 여러 글의 **대화 자료로 선택**을 체크하고 **선택 N개로 질문**을 누릅니다. 키보드에서는 글을 선택하고 `r`로 엽니다.
2. 처음에만 대화를 실행할 프로젝트를 선택하고 질문을 보냅니다. **알림 / 대화** 탭으로 같은 컬럼 안에서 오갑니다.
3. 채널마다 하나의 대화를 계속 이어갑니다. 전송한 자료는 입력창에서 빠지고 대화의 **첨부 자료**에 전송 당시 본문·제목·시간·원문 링크로 남습니다. 후속 질문은 새 글을 붙이거나 기존 대화만 이어갈 수 있습니다. 검색·페이지 이동 후에도 자료 선택을 유지합니다.
4. 한 질문에 최대 20개, 합계 256 KiB까지 첨부합니다. 실행 중 보낸 질문은 기존 작업 대기열에 들어가며 **지금 보내기 / 취소**를 지원합니다. ⌘Enter로 큐에 넣은 뒤 입력이나 자료를 바꾸지 않고 다시 누르면 방금 넣은 질문만 즉시 전달합니다. `#new`·`#fork`는 채널 대화에서 사용하지 않습니다.

수집된 RSS 본문을 자료로 사용하며 링크의 기사 전체를 자동으로 가져오지는 않습니다. 같은 허브의 다른 기기에서도 채널에 연결된 대화를 이어 볼 수 있습니다. 채널 삭제 시 원본 글은 삭제되지만 이미 만든 대화와 첨부한 자료는 작업 기록에 남습니다. 연결된 작업을 삭제하면 다음 질문 때 새 대화를 시작합니다.

봇 채널을 만들면 그 채널에만 입력할 수 있는 토큰을 한 번 표시합니다. 봇의 비밀 설정에 보관하고 `Authorization: Bearer` 헤더로 보냅니다. 기존 허브 접속 토큰으로 발행하지 않으며, 채널 토큰은 작업·승인·채널 관리 권한을 주지 않습니다. 이 Mac의 localhost 관리 접근은 기존처럼 허용되지만, 채널 발행에는 localhost에서도 채널 토큰이 필요합니다. 토큰 재발급은 이전 토큰을 폐기합니다.

관리 창에서 각 봇 채널의 **봇에서 이 채널로 알림 보내기**를 펼치면 채널 ID가 채워진 전송 예제를 복사할 수 있습니다. 봇 환경에 `CHANNEL_TOKEN`을 설정하고 실행합니다. 다른 머신의 봇은 `127.0.0.1` 대신 상단 **다른 기기 연결**의 허브 접속 주소를 사용하세요. 복사 예제에는 실제 발행 토큰을 넣지 않습니다.

```sh
curl -X POST "http://127.0.0.1:4317/api/channels/$CHANNEL_ID/entries" \
  -H "Authorization: Bearer $CHANNEL_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"external_id":"build-42","title":"빌드 완료","body":"테스트를 통과했습니다.","url":"https://example.com/build/42"}'
```

`external_id`는 소스의 안정적인 식별자입니다. 같은 채널에서 같은 ID를 재전송하면 중복을 만들지 않고 내용을 갱신하며, 최초 수신 순서와 읽음 위치를 유지합니다. `{ "entries": [...] }`로 최대 100개를 한 번에 보낼 수도 있습니다. 응답은 `created`, `updated`, `unchanged` 건수입니다.
